## Подготовка и запуск

Нужен Python 3.10 или новее. Внешних библиотек для приложения нет.
Сборка не требуется. В PowerShell из корня проекта:

```powershell
py -3 -m venv .venv
.\run.bat
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`run.bat` выбирает `.venv`, затем `py -3`, затем `python`, передаёт все
аргументы и возвращает код завершения программы. Рабочий каталог — корень
проекта; относительные пути параметров отсчитываются от него.
При прямом запуске `python -m src.shell_emulator.main` пути считаются от cwd.

## Структура и проверка качества

`src/shell_emulator/` — приложение; `tests/` — тесты текущего этапа;
`run.bat` — запуск; `.gitignore` — исключение служебных файлов.
Файл `tests/test_quality.py` проверяет структуру, длины, аргументы,
docstrings, snake_case и числовые литералы в сравнениях.
Внешняя проверка при разработке: flake8 с pep8-naming и сложностью ≤10,
radon. Ограничения: файл ≤1000 строк, Python-строка ≤80 символов,
функция ≤40 строк, аргументы ≤7. Данные VFS не распаковываются на диск.

## Интерфейс и команды

Консольный REPL, приглашение `username@hostname:~$` использует реальные
данные ОС. Парсер поддерживает одинарные/двойные кавычки и экранирование
через shlex. Пустой ввод пропускается; ошибки не завершают REPL.
`exit` без аргументов, EOF или Ctrl+C завершают сеанс.

`ls` выводит имена, `ls -l` также владельцев. `cd [путь]` меняет каталог;
без пути — корень. Поддержаны `/`, `.`, `..`, абсолютные и относительные
пути внутри VFS. Путь с пробелами нужно заключать в кавычки.
Ошибки типа узла, отсутствующего пути и лишних аргументов диагностируются.

`head путь` / `tail путь` выводят первые/последние 10 строк UTF-8 файла.
Они принимают ровно один путь; флаги не поддерживаются.
`history` без аргументов выводит нумерованную историю сеанса, включая
startup, ошибочные команды и сам вызов history. Пустые строки не входят.

`chown владелец путь` изменяет владельца файла или каталога в памяти.
Пустое имя владельца запрещено. `ls -l` показывает результат; повторная
загрузка исходного XML возвращает исходных владельцев.

## Интерактивная демонстрация

```text
ls
cd "my folder"
unknown
cd "unfinished
exit
```

Пример показывает обычный ввод, аргумент с пробелом, неизвестную команду
и ошибку кавычек. Для реальной VFS отсутствующий каталог даёт ошибку.

## Конфигурация и startup

`--vfs` задаёт путь XML; `--script` задаёт UTF-8 startup-скрипт.
Оба параметра необязательны. Значения печатаются при старте.
Startup показывает приглашение с командой и результат, пропускает пустые
строки, останавливается при первой ошибке с номером строки и кодом 1.
Ошибка чтения/кодировки также даёт код 1. После успешного скрипта запускается
REPL, а `exit` в скрипте завершает процесс с кодом 0.

```powershell
.\run.bat --vfs vfs/several_files.xml --script startup.txt
.\run.bat --script scripts/startup_errors.txt
.\scripts\test_all_parameters.bat
.\scripts\test_errors.bat
```

`startup.txt` демонстрирует успешные команды текущего этапа.
`scripts/error_*.txt` демонстрируют ошибки отдельно, поскольку startup
останавливается на первой ошибке. Строка `never_run` не должна выполняться.
Пять положительных BAT-проверок (`test_minimal`, `test_several_files`,
`test_nested`, `test_script`, `test_all_parameters`) каждая проверяют
все параметры: отдельно и совместно. `test_errors.bat` ожидает ошибки.

## Формат VFS и примеры

XML: корень `<vfs name="/">` (допустим также `directory`), внутри
`directory` и `file` с уникальными именами среди соседей.
Файл содержит текст UTF-8 или `encoding="base64"` с двоичными данными.
Необязательный атрибут `owner` задаёт владельца; по умолчанию `root`.
Некорректные XML, узлы, имена, дубликаты и Base64 вызывают ошибку загрузки.
Без `--vfs` создаётся пустой корень в памяти.

```xml
<vfs name="/">
    <directory name="home">
        <file name="hello.txt">Hello world</file>
        <file name="binary.bin" encoding="base64">//4A</file>
    </directory>
</vfs>
```

`vfs/minimal.xml` — минимальное дерево, `several_files.xml` — несколько
файлов, `nested.xml` — три вложенных каталога и файл внутри.
`base64.xml` и `binary.xml` демонстрируют Base64, `invalid.xml` и
`invalid_base64.xml` — ошибки. Дополнительная демонстрация глубины:

```powershell
.\run.bat --vfs vfs/nested.xml --script scripts/startup_nested.txt
.\scripts\test_minimal.bat
.\scripts\test_several_files.bat
.\scripts\test_nested.bat
```

Изменение каталогов, чтение и смена владельца не обращаются к файловой
системе хоста. XML читается лишь при загрузке, изменения не записываются.

## Функции исходного кода

### `config.py`

- `parse_arguments` — Парсит параметры запуска эмулятора.

### `main.py`

- `create_prompt` — Возвращает приглашение с реальными пользователем и хостом.
- `execute_ls` — Выводит содержимое каталога, с владельцами для -l.
- `execute_cd` — Меняет текущий каталог; без аргумента переходит в корень.
- `execute_text` — Выводит первые или последние десять строк UTF-8 файла.
- `execute_history` — Выводит историю с номерами, включая сам вызов history.
- `execute_chown` — Изменяет владельца узла только в оперативной памяти.
- `execute_command` — Проверяет команду и преобразует ошибки VFS в статус.
- `execute_line` — Разбирает строку и возвращает результат выполнения.
- `run_interactive_mode` — Читает команды до exit, EOF или прерывания пользователем.
- `run_startup_script` — Показывает ввод/вывод; останавливается на первой ошибке.
- `main` — Печатает конфигурацию, выполняет startup, затем запускает REPL.

### `parser.py`

- `parse_command` — Разбирает строку команды на имя команды и аргументы.

### `vfs.py`

- `__init__` — Создаёт узел без привязки к файловой системе хоста.
- `__init__` — Создаёт пустой корневой каталог.
- `load` — Атомарно заменяет дерево после проверки XML и Base64.
- `_parse_node` — Проверяет узел и рекурсивно строит дочерние узлы.
- `_parse_file` — Читает текст или строгие Base64-данные файла.
- `resolve` — Разрешает относительный/абсолютный путь внутри дерева VFS.
- `_find_child` — Находит дочерний узел или сообщает об отсутствии.
- `list_directory` — Возвращает элементы текущего каталога.
- `change_directory` — Переходит в каталог, сохраняя состояние при ошибке.
- `get_current_path` — Возвращает абсолютный путь текущего каталога.
- `decode_data` — Декодирует Base64 без игнорирования неверных символов.
- `get_file` — Возвращает файл по пути внутри VFS.
- `change_owner` — Изменяет владельца файла или каталога только в памяти.

## Единая кодировка примеров VFS

Во всех корректных XML-примерах содержимое каждого `file` хранится
с `encoding="base64"`, включая текстовые файлы. После декодирования
исходные байты и переносы строк сохраняются. Сам XML остаётся UTF-8.
`minimal.xml` не содержит файлов. `invalid.xml` намеренно не закрыт,
а `invalid_base64.xml` содержит неверный Base64 для проверки ошибок.
